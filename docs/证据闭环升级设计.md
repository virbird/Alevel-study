# 证据闭环升级设计（借鉴 DeepTutor，v0.1.5+ 分阶段实施）

> 状态：设计定稿，未实施。按 P1→P5 优先级逐步落地，每阶段独立可发布。
> 源起：分析 HKUDS/DeepTutor 后确定的借鉴方向——三层可审计记忆、掌握度门槛显性化、
> 复习产物编译、学习数据可视化。核心原则不变：本地优先、不代写、vault 数据可审计。

## 总体思路：一条数据链，不是五个孤立功能

```
P1 采集（错题↔会话回链）
   ↓
P2 呈现（掌握度进度 + 行内直达练习）
   ↓
P3 综合（L2 本地弱点综述 → 反哺注入省 token）
   ↓
P4 产物（复习单编译 + 漂移检测）
   ↓
P5 增强（趋势 SVG / 英文复盘 diff）
```

上游供数据给下游；P1/P2 不依赖任何新概念，P3 是核心差异化，P4/P5 锦上添花。

## 通用约束（所有阶段遵守）

1. **命名**：新建文件用英文名，放入既有中文目录（如 `记录/weakness-profile.md`）；
   文件内表头/结构保持中文，与既有台账一致（便于 ID 互相回链，UI 显示层负责翻译）。
2. **i18n**：所有新 UI 文案进 `src/i18n.ts` en/zh 双字典；状态值显示走 `statusLabel()`。
3. **零 LLM 依赖**：P1–P4 全部本地统计/拼装，不新增模型调用（L3 例外，明确标注）。
4. **测试**：每阶段追加 UT+FVT 并全量跑通（当前基线 431 项）。
5. **兼容**：台账加列采用"读时宽容（旧行缺列取空）、写时全列"策略，不迁移旧数据。

## P1 错题本 ↔ 会话回链（半天）

**目标**：错题条目能一键打开"当时做错的那场会话"，复习从「同考点变式」升级为「重做原题」。

### 数据模型
- `记录/错题本.md` 表尾加一列 `会话`（第 9 列），存 `<sessionId>-<mode>`（不含 .md 后缀）。
- `WrongAnswerEntry` 加字段 `session: string`（可空）。
- 旧 8 列行解析时 `session = ''`；`addEntry`/`updateStatus` 重写为 9 列。

### 写入点
- `MainView.renderWrongAnswerPrompt` 确认入库时带 `${this.sessionId}-${String(this.mode)}`。
- 口语错题入库（speaking register）同样带当前会话。
- 线下反馈（OfflineFeedbackModal）入库的条目 session 留空。

### UI
- 记录中心错题本表：新列「会话」，有值时渲染为链接，点击 `open(\`${ROOT}/会话/${session}.md\`)`；
  文件不存在（会话未存档，如零交互被跳过）时 Notice 提示"会话尚未存档"。
- 复习页签错题队列行：有回链时加「原会话」小按钮。

### i18n keys
`records.cols.wrongs` 追加列名；`wrong.sessionLink` / `wrong.sessionMissing`。

### 测试
- UT：9 列写入/8 列旧行解析兼容/updateStatus 保留 session。
- FVT：订正闭环入库后条目含当前 sessionId。

### 指标
错题「未订正→已订正」转化率（P3 落盘后周报可见）。

## P2 掌握度门槛显性化 + 行内直达练习（1 天）

**目标**：把散在代码里的升级规则变成可见进度；差一步的条目给行动按钮。

### 规则来源（以现有代码为准，不改变规则本身）
| 台账 | 跃迁规则（已核实） |
|------|-------------------|
| 术语 | 未稳定 --通过1次--> 观察中 --通过1次--> 已稳定（`TermService.applyDrill`） |
| error-log | 未消除 --复查通过--> 观察中 --再通过--> 已消除（MainView 复查按钮） |
| 错题 | 未订正 --学生重做完成--> 已订正 |
| 表达 | SM-2 间隔档位，到期抽查（`ExpressionService.due`） |
| 章节 | 锁定→解锁→已掌握（手动，已有按钮） |

### UI（记录中心 + 复习页签）
- 状态列旁加进度徽章（muted 小字）：
  - 术语「观察中」→ `1 次抽查即稳定`；「未稳定」→ `还需 2 次抽查`
  - error-log「观察中」→ `1 次复查即消除`
  - 错题「未订正」→ `重做一次即订正`
- 行内行动按钮「去练」：
  - 术语行 → 切到 drill 模式，预填 `抽查术语「X」`（复用 `variant.prefill` 的预填模式）
  - error-log 行 → 复用现有变式复查预填
  - 错题行 → 预填 `重做错题：「topic」（我当时的错误：myError）`，有 P1 回链时在任务文本
    末尾附 `原会话见 会话/<session>.md`
- 变式防重（原独立建议并入此处）：变式预填文本追加该考点最近一次变式日期，
  提示 AI「换一个角度，避免与近期变式雷同」——纯提示词文本，零数据结构。

### i18n keys
`progress.term.one` / `progress.term.two` / `progress.log.one` / `progress.wrong.redo` /
`records.action.practice` / `records.action.redo` 等（en/zh 成对）。

### 测试
- UT：进度徽章文案函数（状态→徽章 key 映射）。
- FVT：错题行「去练」预填文本含 myError 与回链。

### 指标
复习页签四队的周清除数（P3 落盘）。

## P3 L2 本地弱点综述 + 注入替换（2–3 天，核心）

**目标**：把洞察引擎的本地统计沉淀为可审计的弱点画像文件；用综述替代原始台账行注入，
既让个性化可见可改，又压缩 system prompt token。

### 数据模型
新文件 `记录/weakness-profile.md`（单文件，H2 按科目分节）：

```markdown
---
updated: 2026-08-12
---
# 弱点画像（插件生成，可手改；手改内容在下次生成时保留于「人工备注」节）

## Maths
- 高频失分码（近30天）：E ×5、DV ×3（证据：#012 #015 #018）
- 复发热点：Quadratic inequalities 复发 3 次（证据：#007）
- 术语：未稳定 4 个（binomial expansion、…）
- 错题未订正：2 条（证据：W003 W008）

## 人工备注
（学生/家长手写区，生成时原样保留）
```

- 每科 ≤6 行；每行末尾用台账 ID 回链（error-log ID / 错题本 ID）= **可审计**。
- 「人工备注」节在重新生成时原样保留（解析后回写）。

### 服务层
- `InsightEngine.buildL2Profile(entries, terms, was, tags): string` —— 纯本地统计，
  复用现有 `codeCounts` / `topicHeat` / 复发过滤逻辑。
- 新 `ProfileL2Service`（或并入 InsightEngine）：`generate()` 写文件、`loadSection(subject)` 读科目节、
  `isFresh()` 检查 frontmatter updated ≤7 天。
- 触发：① 结题入库流程末尾自动刷新；② `StatsService.runHotspotBiweekly` 时一并刷新；
  ③ 记录中心手动「重新生成」按钮。

### 注入替换（PromptAssembler）
决策规则（固定，不加设置项）：
- 未消除失分 >10 条 **且** weakness-profile 新鲜 → 注入该科目综述节替代 `renderUnresolved` 全表；
  注入块标题 `插件注入：弱点画像（完整台账见 记录/weakness-profile.md）`。
- ≤10 条或综述过期 → 维持现状全表注入（小数据全表更精确）。
- 错题注入同理：>5 条时仅注入综述行 + 条数，≤5 条保持逐条。

### 周清除率落盘
`StatsService` 每周向 `记录/统计分析.md` 追加一行快照：
`| 日期 | 未消除数 | 未稳定术语数 | 未订正错题数 | 到期表达数 |` —— P1/P2/P4 的指标全部由此读取。

### L3（跨科综合画像）——本期不做
周报 `buildWeekly` 已是雏形；若将来做，为「按需一次 LLM 调用生成学期画像」，独立按钮触发。

### i18n keys
`inject.profile.title` / `records.profile.regen` / `profile.l2.header` 等；
综述文件正文表头中文（数据文件约定），UI 按钮双语。

### 测试
- UT：buildL2Profile 输出含 ID 回链；人工备注节保留；>10 条切换注入模式、≤10 条回退。
- FVT：结题后 weakness-profile 刷新；system prompt 含综述且不含全表。
- token 对照：估算（`utils/tokens.ts`）综述模式 vs 全表模式的注入长度，断言下降。

### 指标
平均 system prompt token（summary 已展示组成，另记入统计分析快照）。

## P4 复习单编译 + 漂移检测（1–2 天）

**目标**：把「复习队列」从四张表变成一页可读、可打印、可带去线下的成品。

### 产物
`记录/review-sheet.md`，纯本地拼装（不调 LLM），复习页签顶栏「生成复习单」按钮触发：

```markdown
---
generated: 2026-08-12
fingerprint: <md5(各源台账 行数+ID串)>
---
# 复习单 2026-08-12

## ① 术语闪卡（未稳定 4 + 观察中 2）
> [!question]- binomial expansion 的定义有几个成分？
> （自测后展开对照：台账 记录/术语清单.md #12）

## ② 错题重做（复发≥2 失分 + 未订正错题）
- [ ] Quadratic inequalities（E，复发3）：出同陷阱变式重做 —— 原会话 会话/xxx.md
- [ ] W003 杠杆平衡：重做原题（我当时错在：只列一个力矩）

## ③ 表达造句（到期 3 条）
- [ ] in stark contrast to —— 造一个雅思语境句
```

- 闪卡用 Obsidian callout 折叠语法 `> [!question]-`，原生支持自测交互。
- 任务行带台账 ID 与 P1 会话回链，可直接复制进教练页签开练。

### 漂移检测
- fingerprint = 各源台账（error-log 到期集、术语未稳定集、错题未订正集、表达到期集）的
  行 ID 串 md5。
- 复习页签渲染时对比当前 fingerprint 与文件 frontmatter：不一致 → 顶栏徽章
  「复习单已过期，点击重新生成」。生成即覆盖旧文件（产物可再生，不留版本）。

### i18n keys
`review.sheet.generate` / `review.sheet.stale` / `review.sheet.done`；
单内小节标题中文（数据文件约定）。

### 测试
- UT：fingerprint 稳定性（同数据同串）；四节内容来源正确；空队列节省略。
- FVT：生成→修改台账→检测过期→重生成闭环。

### 指标
统计分析快照中"到期项总数"的周环比（复习单是否加速清除）。

## P5 视觉增强（各半天，可选）

### 5a 本地 SVG 趋势图
- 手写 SVG 字符串生成器 `src/utils/svgChart.ts`：`sparkline(values)` 折线 +
  `bars(pairs)` 条形，无第三方依赖。
- 接入点：记录中心②雅思批改（总分折线）、⑦口语记录（总分折线）、
  ①失分点分区顶部（近 30 天失分码条形分布）。
- 颜色用 Obsidian CSS 变量（`var(--interactive-accent)`），自动适配主题。

### 5b 英文复盘 before/after diff
- 六部结题②「英文作答复盘」中学生自己写的两版对照（不是 AI 改写，不碰教学原则）。
- 提示词增量：复盘完成时输出机器块 `{"answerReview": {"before": "...", "after": "..."}}`
  （9 份英文 + 9 份 .zh.md 提示词同步加一段，内容一致）。
- MainView 检测该块 → 渲染「对照」按钮 → Modal 内词级 diff（本地 LCS，
  删除词红色删除线、新增词绿色高亮）。
- 不入台账（会话存档已含全文），纯展示。

### 测试
- UT：sparkline/bars 输出合法 SVG；LCS diff 边界（空串/全同/全异）。
