## 1. 产品定位

**一句话**：一个长在 Obsidian vault 里的 A-Level 学习**辅助**教练——主学习发生在线下（学校、课本、作业），学生在**需要协助时**才打开它：概念不懂、题目卡住、作文批改。插件把每次求助记录下来，通过统计「问了什么、错了什么、还在问什么」发现当前学习弱点，给出建议；学生同意后，再生成具体的学习建议。AI 只引导不代劳，数据全部是本地 Markdown。

**使用模型（拉式，不是推式）**：

```
线下主学习 ─遇到问题─▶ 打开插件求助（概念/卡题/作文）
                          │
                          ▼ 自动记录：问了什么科目、什么考点、什么类型的困惑
                          ▼ 统计分析：提问热点 × error log × 术语状态 交叉
                          ▼ 发现弱点 → 给建议（一张卡片，不打断不强推）
                          ▼ 学生同意 → 生成学习建议（带回线下执行）
```

**它不是什么**：
- **不是核心学习框架**——不接管日程、不要求每天打卡、不制造「今天必须用我」的压力；用得少但每次有效，才是成功
- 不是通用 AI 聊天插件（那是 AI Study Buddy 已经做的事）
- 不是题库 App（不内置 past paper，不编造出处）
- 不是替学生做题的工具（继承提示词体系的最高原则：不给答案，只提问引导）

**与 AI Study Buddy 的关系**：复用其 Provider / SM-2 / 聊天 UI 等基础设施，但产品重心从「通用学习助手」收窄为「A-Level + 雅思的按需教练 + 弱点发现器」——所有功能围绕一份长期学习档案（学生参数、求助记录、失分记录、术语清单）运转，而不是围绕单次对话。

## 3. 核心问题与解法

| 用户痛点 | 现状（纯 prompt + 手工文档） | 插件解法 |
|---|---|---|
| 每次都要手动粘贴 prompt、学生参数、error log | 复制粘贴繁琐，经常漏发「未消除」条目 | 一键进入学科教练模式，自动注入 prompt + 学生档案 + 未消除失分行 |
| 求助行为本身是最真实的弱点信号，但没人统计 | 问完就忘，同一个概念问了三次自己意识不到 | 每次求助自动打标（科目/考点/困惑类型），统计发现提问热点 |
| 弱点发现了不知道怎么办 | 老师反馈零散，自己总结难 | 提问热点 × error log × 术语状态三源交叉 → 建议卡片 → 同意后生成学习建议 |
| 记录靠自觉，AI 生成的 log 行经常忘了粘 | error-log.md 手工维护 | 结题时自动解析 AI 输出的 log 行，一键入库 |
| 复习没人督促，复查日期形同虚设 | 靠自己记 | 打开 Obsidian 时温和提醒到期复查与抽查（不接管日程，只提醒插件内的事） |
| 抽查无题源、AI 不记得练过什么 | 术语清单手工维护，AI 凭印象抽 | 术语清单结构化存储，抽查时插件把清单喂给 AI，随机抽取 |
| 不知道自己在朝目标前进还是原地打转 | 无统计 | Dashboard：DV/CL/LK 趋势、提问热点、复发热点、雅思分项走势 |
| 已有的学习基础没有起点记录，补录门槛高 | 要么从零开始，要么手工整理一大堆历史 | 随手记 + AI 结构化：用自己的话描述现状/进展，AI 提取成结构化条目，确认后入库，允许模糊、逐步补全 |

## 4. 功能模块

### 4.1 学习档案（Profile）— 一切功能的地基

一份 `档案.md`（frontmatter 结构化），插件设置页可视化编辑：

```yaml
stage: G10            # G10 / G11 / G12
subjects:
  Maths:      { level: "IG+AS", bias: "AS主导", target: "A*" }
  Physics:    { level: "IG+AS", bias: "IG主导", target: "A*" }
  CS:         { level: "IG+AS", bias: "IG主导", target: "A*", language: "Python" }
  Chemistry:  { level: "IG", target: "A*" }
  Economics:  { level: "IG", target: "A*" }
ielts: { target: 7.5, current: null, focus: "Writing" }
oxbridge: { direction: "待定", exams: ["TMUA", "MAT"], enabled: true }
independent_minutes: 15   # 独立思考门槛，随阶段自动建议调整
```

- 档案变化自动传导到所有 prompt（如 `阶段内偏重` 改为 AS 主导 → 数学教练自动切换 20 分钟门槛）
- README 中的「待确认事项」做成档案里的待办字段，确认一项少一项

### 4.2 弱点发现与学习建议（Insights）— 本产品的价值核心

主学习在线下，插件看不到课堂和作业——但它能看到最真实的信号：**学生什么时候、为什么来求助**。

**提问记录（自动，零操作成本）**：
- 每次教练会话结束时，AI 顺带输出一行会话标签：科目 / 考点(EN) / 困惑类型（概念不懂 / 会但不熟 / 卡在某步 / 术语表达 / 作文批改）/ 求助深度（问一句就懂 / 需要完整引导）
- 插件解析后追加到 `提问记录.md`，学生无需任何操作——这是唯一不需确认的自动记录（它只是行为日志，不是学习结论）

**弱点分析（三源交叉，每周自动跑一次）**：

| 数据源 | 信号 |
|---|---|
| 提问记录 | 同一考点反复求助、某科求助频率突增、困惑类型分布（概念型多=基础不牢，卡步型多=熟练度不够） |
| Error log | 复发热点、DV/CL/LK 趋势、未消除堆积 |
| 术语清单 / 雅思分项 | 长期「未稳定」的术语、LR/GRA 短板 |

- 交叉才有价值：「moments 提问 3 次 + error log 里 G 码（作图）未消除 + work done 术语未稳定」→ 弱点不是「moments 不会」，而是「力矩方向判断 + 图示表达」

**建议卡片 → 同意 → 学习建议（两段式，征得同意是硬性步骤）**：
1. **建议卡片**：分析发现弱点后，在 Dashboard 出一张卡片（不弹窗不打断）：「最近两周你在 Physics 的 moments 上求助 3 次，且图示类失分未消除——要不要看看针对性建议？」三个动作：看建议 / 以后再说 / 不准确（反馈修正分析）
2. **学习建议**（仅在同意后生成，落为 `建议/` 下的 Markdown）：弱点诊断 + 线下可执行动作（如「这周练 3 道杠杆平衡变式，画图先标受力点」）+ 插件内配套动作（如「术语抽查加入 moment 定义」）。**建议是带回线下执行的，不是插件内的任务流**，不排日程表

**三年路线图**保留为参考文档（README 路线表为默认模板）：它是建议生成时的背景约束（如 G10 不碰 STEP），而不是日常执行计划。周计划 / 每日待办不再作为核心功能，仅在学生主动要求时由学习建议附带生成一份轻量 checklist。

### 4.3 学科教练（Coach Chat）

基于 AI Study Buddy 的聊天视图改造：

- **科目即会话模式**：选择 Maths/Physics/Chem/CS/Econ/精练模式/雅思写作，插件自动组装 System Prompt =「对应 prompt 主体 + 档案参数 + 未消除 error log 行 + 本期专项」
- prompt 文件存放在 vault 的 `prompts/` 目录，**用户可直接编辑**（保持现有 6000 字符纪律），插件只做注入不做硬编码
- **结题自动落库**：AI 按提示词约定输出的「一行 log 记录」「术语清单行」被插件解析，弹出确认卡片，一键写入 error log / 术语清单（自动补 ID、日期、复查日期）；同时自动追加会话标签到提问记录（见 §4.2）
- **独立思考计时器**：进入思维题时可启动倒计时（15/20 分钟按档案），未到门槛时输入框提示「还没到求助时间」——把提示词里的软约束变成产品硬约束
- 兴趣延伸条款保持 prompt 层实现，插件不干预

### 4.4 记录（Records）

五本核心账本，全部 Markdown 表格 + 插件视图。失分信息按三层分流（v0.4 新增）：

| 层级 | 特征 | 去处 | 处置机制 |
|---|---|---|---|
| 具体失分 | 做了具体某题，犯了具体错 | Error Log 主表 | 变式题复查，可判定消除 |
| 题型/习惯倾向 | 成功率不高、容易口语化等 | 练习侧重 | 注入教练 prompt，遇对应题型加强审查，无法变式题消除 |
| 科目级模糊印象 | 说不出考点的自述 | 弱点印象 | 待验证先验，等具体证据积累（Phase 2 关联） |

1. **Error Log**（直接采用现有代码体系：基础码 + CS/Chem/Econ 扩展码 + DV/CL/LK 重点码）
   - 插件视图支持：按科目/代码/状态筛选、复发自动 +1（同「考点+代码」不新增行）、状态流转（未消除→观察中→已消除）
   - 复查日期规则内置：默认 7 天，复发条目 3 天
2. **术语清单**（drill-definitions 的配套模板结构化）
   - 字段：Term / 教材原文（学生手抄，AI 不代填）/ 必要成分 / 漏过的成分 / 用错的口语词 / 状态
   - 状态流转：未稳定 → 观察中 → 已稳定（连续两次抽查通过）
3. **雅思写作档案**
   - 每篇作文一个笔记：原文 + AI 批改（四维分项）+ 修订版 + 失分点
   - 高分表达自动汇入「表达积累库」（分词汇/短语/句型），进入抽查题源
4. **练习侧重**：题型/作答习惯倾向（日期/科目/描述/状态：生效中→已缓解），注入教练 prompt 影响训练侧重
5. **弱点印象**：模糊自述（日期/科目/描述/证据数/状态：待验证→已确认/已作废），不进复查队列

### 4.5 复习与抽查（Review & Spot-check）

复习提醒只覆盖**插件内产生的记录**（error log 复查、术语抽查、表达库），不接管线下学习日程——它提醒的是「你在这里留过的尾巴」，不是「你今天该学什么」。

**复习队列**（到期驱动）：
- Error log 到期条目 → **不重做原题**，插件调用 AI 出同考点、同陷阱的变式题（复用提示词的变式机制），做完更新状态
- 术语清单 → 模式 E 随机抽查：插件随机抽 3 条喂给 AI，30 秒盲写，AI 只标「完整/漏成分/有口语词」
- 雅思表达库 → 抽表达要求造句
- 一次复习 5–10 分钟就能完成——它是线下学习的缝隙填充物，不是另一块大任务

**提醒机制（默认温和，强度可配）**：
1. 打开 Obsidian → 状态栏徽标显示待复习数（如 `📌 5`），不弹窗
2. 到期未处理 → 每日首次打开弹一次 Notice：「有 3 条失分点到期复查，预计 8 分钟」，当天不再重复
3. 长期堆积（如 ≥2 周）→ 不升级骚扰，而是转为弱点分析的输入：「复查长期堆积」本身作为一张建议卡片出现（「积了 12 条，要不要挑 3 条最痛的处理掉？」）
4. 队列按「复发次数×等待天数」排序，最痛的排最前，时间有限时只做最前面的

**抽查的不可预测性**：每周从「已稳定/观察中」条目里随机回抽 1-2 条（防止假性掌握），这是「抽查」区别于「复习」的关键。

### 4.6 雅思专线（IELTS Track）

- **写作批改工作流**：新建作文笔记 → 命令「批改当前作文」→ 注入 ys.md prompt → 六段结构化输出回填到笔记对应小节
- **分项趋势**：每篇的 TR/CC/LR/GRA 四维分数入库，Dashboard 画走势线，距 7.5 目标的短板维度高亮
- **与 A-Level 协同**（这是本产品独有的联动点）：Error log 中的 E/CL/DV 码本质与雅思 LR/GRA 是同一能力。Dashboard 把「学科英文表达码趋势」与「雅思 LR/GRA 分数」并排展示，强化「练术语=练雅思」的正反馈
- **口语**：插件内语音训练（模考/陪练/评分报告，见 §4.10）；仍保持辅助定位：主动发起才练，不打卡
- 听力/阅读：不做批改不做打卡（线下主学习范畴），仅在学习建议里作为线下动作出现

### 4.7 牛剑延伸（Oxbridge Track，兴趣驱动，默认低调）

- 档案里 `oxbridge.enabled` 开启后，Dashboard 出现「进阶角」：按阶段解锁（G10 上=UKMT 风格思维题，G10 下=TMUA/MAT 入门，G11 起 STEP）
- 思维题走数学教练 prompt 的思维题分支，强制独立思考计时
- **不主动推送**：仅在复查队列清空、或学生主动打开进阶角时展示思维题，符合「有兴趣的情况下尝试」的定位
- 内置提醒：进阶考试要求每年可能变化，正式备考前核对官方页面

### 4.8 随手记与渐进式录入（Quick Capture）— 数据录入哲学

**核心理念**：学生不是从零开始，也不该被表格吓退。所有结构化数据都可以从一句自然语言开始，由 AI 提取、学生确认、逐步补全。**允许模糊，拒绝空白。**

**冷启动（首次使用的引导对话）**：
- 插件首次启动进入一次轻量对话：「用你自己的话说说，各科现在学到哪了？最近哪些地方老丢分？」
- 学生随意作答（如「数学 AS 学到 differentiation，物理上周考试受力分解又错了，化学感觉方程式配平还行」）
- AI 提取为候选条目：各科进展基线 + error log 种子行 + 术语清单候选，逐条卡片式确认入库
- **不要求一次说全**——冷启动 10 分钟能记多少记多少，之后靠随手记持续补

**随手记（日常入口，命令 / 快捷键随时唤起）**：
- 一个输入框，学生用任何表达写：「今天讲了 moments，杠杆平衡的题第一次做基本都对」「opportunity cost 定义又漏了 next best」
- AI 判断这句话属于哪类信息并提取：
  - 学习进展 → 更新对应科目的进展记录
  - 失分线索 → 生成候选 error log 行（考点/代码由 AI 建议，学生可改）
  - 术语问题 → 生成候选术语清单行
  - 都不像 → 存为普通学习日志，不强行归类
- 每条提取结果都有确认步骤（改/收/丢三个动作），符合「学生是操作者」原则

**进展记录的宽松模型**：
- 每科一份 `进展.md`，条目只要求「日期 + 一句话」，syllabus 章节对应关系是**可选**字段
- AI 在教练模式开场时读取最近进展，用于判断「他大概学到哪了」——不需要精确的知识点勾选表
- 学生想精确时可以精确（挂 syllabus 编号），不想时一句话也能用——严格程度由学生决定，插件两头都支持

### 4.10 雅思口语训练（Speaking）— v0.4 新增

完整技术方案见 `docs/雅思口语助手-Obsidian插件-项目设计.md`（架构/状态机/录音/Provider/风险对策）；本节只记集成进本插件的产品决策。

**定位**：GPT-Live 式 AI 考官练习——模拟考试 + 自由陪练，考后结构化评分反馈。仍守辅助定位：主动发起才练、不打卡；练习记录是副产品不是目标。

**两种模式**：

| 模式 | 描述 | 优先级 |
|---|---|---|
| 模拟考试 | Part1 → Part2（1min 准备 + 2min 陈述）→ Part3 完整流程；阶段切换由**代码状态机**驱动（轮次+计时），LLM 只在阶段内扮演考官，流程稳定不失控 | P0 |
| 自由陪练 | 选一个话题与 AI 考官自由对话，不限时 | P0 |

**语音链路（全部可选配置，逐级降级）**：
- LLM：复用插件现有全局模型配置（LlmClient），不另设一套
- ASR / TTS / 发音评测：新增讯飞/阿里云语音 Provider 设置；**未配置时退化为文字模式**（打字作答、考官问题文字显示），保证无语音 API 也能用（对应口语设计文档 Milestone 1）
- 发音评测为 P1：用 ASR 结果作 refText 评「发音清晰度」而非内容，报告中明确告知；评测失败静默降级不阻塞对话
- 录音统一转 16kHz 单声道 WAV（纯 Web API，桌面/iPad 行为一致）；音频是可选附件（saveRecordings 开关），不破坏「数据以 Markdown 为主」原则

**题库即 Markdown**：`StudyCoach/雅思/题库/` 下的题组文件（frontmatter + Part1/2/3 结构），首次启动释放内置当季常考题；用户可自由编辑扩充；插件声明题库为社区整理，需自行核实

**考后报告与记录沉淀（与现有雅思体系打通）**：
- LLM 生成雅思四维评分（FC/LR/GRA/P，P 取发音评测均分映射，无评测时标注缺失）→ ReportModal 预览 → 确认后写入练习笔记（frontmatter 结构化分数，Dataview 友好）
- 口语分数进分数台账，与写作趋势并排展示（雅思总分趋势 = 写作 + 口语）
- 错词/语法错误/高分替换沉淀进 `口语错题本.md`（发音/语法/词汇三类）进入复习队列；高分表达进现有表达积累库（与写作共用 SM-2 抽查）
- 每轮录音随练习笔记保存，笔记内可回放

**交互**：新增「口语」页签（语音交互与文字教练形态差异大，独立承载）：按住说话（PointerEvent 兼容 iPad）、考官播报可打断、Part2 准备 60 秒倒计时 + notes 草稿纸；命令：开始模考 / 自由陪练 / 打开口语面板

**考官 prompt 约束**：每次回复 <40 词（TTS 播报体验）；一次只问一个问题；不讲解不教学不跳出考官角色；Part3 目标分 ≥6.5 时每话题挑战一次观点

## 5. 数据模型（vault 目录结构）

一切数据都是用户可见、可手改的 Markdown——插件坏了/卸载了，数据完好且仍可配合纯 prompt 使用（向下兼容现有工作流）。

```
vault/
├── StudyCoach/
│   ├── 档案.md                    # frontmatter 结构化学生参数
│   ├── 三年路线图.md              # 参考文档，建议生成时的背景约束
│   ├── 建议/
│   │   └── 2026-08-04-physics-moments.md  # 同意后生成的学习建议，按次分文件
│   ├── 记录/
│   │   ├── error-log.md           # 主表，格式与现有模板一致
│   │   ├── 提问记录.md            # 每次求助自动追加：日期/科目/考点/困惑类型/深度
│   │   ├── 术语清单.md
│   │   ├── 复发热点.md            # 每两周自动统计生成
│   │   ├── 练习侧重.md            # 题型/习惯倾向，注入教练 prompt
│   │   ├── 弱点印象.md            # 模糊自述，待验证先验
│   │   ├── 进展/                  # 每科一份，条目=日期+一句话（可选挂 syllabus 编号）
│   │   │   ├── Maths.md
│   │   │   └── ...
│   │   └── 学习日志.md            # 随手记里无法归类的条目落这里
│   ├── 雅思/
│   │   ├── 作文/2026-08-04-task2-xxx.md
│   │   ├── 批改记录.md               # 写作分数台账
│   │   ├── 表达积累库.md
│   │   ├── 题库/Work-and-Study.md     # 口语题组（frontmatter + Part1/2/3），用户可编辑
│   │   └── 口语/
│   │       ├── 2026-08-07-模考-Work-and-Study.md  # 练习报告笔记（frontmatter 四维分数）
│   │       ├── 口语错题本.md          # 发音/语法/词汇错误沉淀，进复习队列
│   │       └── 录音/…                 # 可选附件（saveRecordings 开关）
│   ├── 会话/                      # 教练对话存档（自动）
│   └── prompts/                   # 六份提示词 + ys.md，首次启动从内置模板生成
└── (用户自己的课程笔记，不受插件管理)
```

索引策略：插件启动时解析上述文件建内存索引，**写入永远以 Markdown 为准**。

**同步友好性（git / iCloud 多机同步是明确需求）**：
- 不使用 sql.js 等二进制存储作为数据源——二进制文件 git diff 不可读、iCloud 冲突无法合并。统计缓存若需要，放在 `.obsidian/plugins/` 下且可随时重建，**删掉不丢任何数据**
- 所有记录文件按「追加为主、行级修改为辅」设计，减少同步冲突面；学习建议按次分文件，天然隔离冲突
- 插件启动时对关键文件做格式校验，发现同步冲突标记（`<<<<<<<`）时提示用户处理而不是覆盖

## 6. 技术架构

```
┌────────────────────── Obsidian Plugin ──────────────────────┐
│  Views: Dashboard │ Insights │ Coach Chat │ Records │ Speaking│
│  ────────────────────────────────────────────────────────── │
│  Domain: ProfileService / InsightService(三源交叉分析)        │
│          SuggestionService(建议卡片→同意→生成)              │
│          SessionTagger(会话打标→提问记录) / ErrorLogService  │
│          TermListService / ReviewScheduler / IeltsService    │
│          PromptAssembler(注入档案+log+专项) / LogLineParser   │
│          QuickCapture(自然语言→候选条目提取与确认)            │
│  Speaking 层（v0.4，语音可选降级）：                          │
│          SpeakingSession(考试状态机) / QuestionBank(MD题库)  │
│          AudioRecorder(统一16k WAV) / AudioPlayer(可打断)    │
│          AsrProvider / TtsProvider / PronEvalProvider        │
│          SpeechScoring(四维聚合) / SpeechLedger(口语台账)    │
│  ────────────────────────────────────────────────────────── │
│  复用自 AI Study Buddy (LLM_Private_Teacher):                │
│    providers/ (Anthropic/OpenAI/Compat + 5 种 CLI)           │
│    spacedRepetition (SM-2，用于术语与表达库)                  │
│    LearningStorage / stats / 聊天 UI 骨架 / i18n             │
└─────────────────────────────────────────────────────────────┘
```

技术决策：
- TypeScript + esbuild，`isDesktopOnly: false`（iPad 可用，CLI Provider 仅桌面）——沿用 AI Study Buddy 配置
- **复用方式（已确认）：fork 而非依赖**：把 `src/core/providers`、`spacedRepetition.ts` 及聊天 UI 骨架拷入新插件裁剪，避免与原插件的通用聊天功能纠缠；`LearningStorage.ts` 的 sql.js 部分不复用（见同步友好性）
- 复查调度：error log 用固定规则（7 天/3 天，与现有模板一致）；术语与表达库用 SM-2
- QuickCapture 实现：一次 LLM 调用输出 JSON（类型 + 提取字段 + 置信度），低置信度条目默认落学习日志而非强行归类
- InsightService 实现：统计部分纯本地计算（频次/趋势/交叉），不调 LLM；仅在同意后生成学习建议文案时调一次 LLM，把三源统计结果作为上下文
- LogLineParser：解析 AI 结题输出中的 `| 日期 | 科目 | ... |` 行与术语清单行，容错（解析失败降级为「手动粘贴」按钮）
- 语音链路（v0.4）：HTTP 走 requestUrl（CORS 豁免）；讯飞 WebSocket 接口用原生 WebSocket + Web Crypto 签名（不用 Node crypto，iPad 兼容）；考试阶段切换由代码状态机控制（轮次+计时），不交给 LLM 自由发挥；ASR 识别与发音评测并行、TTS 按句流水线播放（目标：用户说完 → 考官开口 ≤2.5 秒）

## 7. 关键产品原则（从提示词体系继承，插件层必须守住）

1. **AI 不给答案**——插件不提供任何绕过教练模式的「直接解题」入口
2. **不编造出处**——插件 UI 不展示任何 AI 声称的 paper 年份/题号；需要真题引导用户去官方文件
3. **原文基准**——术语比对必须有学生手抄的教材原文，「教材原文」字段插件永不代填
4. **一个失分点一行，复发不新增行**——入库逻辑硬约束
5. **独立思考门槛**——计时器可跳过但会记一笔 Z 码（放弃太早）候选
6. **学生是操作者**——所有入库都有确认步骤，插件是记录员和提醒者，不是自动化黑箱
7. **允许模糊，拒绝空白**——任何记录都可以从一句自然语言开始，结构化程度由学生逐步决定；插件不设「必填表格」拦路
8. **辅助不接管**——主学习在线下；插件不排日程、不要求打卡、不制造使用压力；提醒只覆盖插件内产生的记录；学习建议必须征得同意后才生成，且面向线下执行

## 8. MVP 与迭代路线

### Phase 1 — MVP（先跑通闭环，约 2-3 周开发量）
- 档案 + prompts 目录初始化
- **冷启动引导对话**：用自己的话描述现状 → AI 提取 → 确认入库（进展基线 + error log 种子）
- Coach Chat：科目选择 → 自动注入 prompt/档案/未消除 log/最近进展
- **会话自动打标 → 提问记录**（数据从第一天开始积累，分析功能 Phase 2 才上）
- Error Log：视图 + LogLineParser 一键入库 + 复发/状态/复查日期规则
- 随手记（基础版）：自然语言 → 候选条目 → 确认入库
- 待复习提醒（状态栏徽标 + 每日一次 Notice）
- 验收标准：**① 冷启动 10 分钟内录入已有基础并开始第一次教练会话；② 一次完整求助（选科→提问→结题→log 入库 + 提问记录自动追加→7 天后收到复查提醒）零复制粘贴**

### Phase 2 — 弱点分析与学习建议（产品价值核心）
- 提问记录统计（提问热点、困惑类型分布）+ 三源交叉分析（每周自动）
- 建议卡片 → 同意 → 学习建议生成（含「不准确」反馈回路）
- 术语清单 + 模式 E 抽查工作流 + 随机回抽
- 复发热点每两周自动统计 → 本期专项（注入教练 prompt）
- 独立思考计时器

### Phase 3 — 雅思专线
- 作文批改工作流 + 四维分数入库 + 趋势图
- 表达积累库 + SM-2 抽查
- 学科表达码 × 雅思分项的联动视图

### Phase 4 — Dashboard 完整版与牛剑延伸
- 弱点雷达 / 目标进度全量图表
- 进阶角（复查队列清空解锁 / 学生主动进入）
- 周报导出（给家长/自己复盘）

### Phase 5 — 雅思口语专线（Speaking，v0.4 新增，按口语设计文档 Milestone 展开）
- **P5a 文字版流程（无语音 API 依赖）**：题库种子 + 考试状态机 + 自由陪练 + 文字输入交互 + 考后报告 + 口语分数进台账（验收：一次完整模考从开始到报告入库，口语趋势与写作并排可见）
- **P5b 语音闭环（桌面）**：AudioRecorder（统一 16k WAV）+ 讯飞/阿里 ASR/TTS + 按住说话 + TTS 可打断
- **P5c iPad 兼容 + 发音评测**：录音格式适配真机验证；讯飞 ISE / 阿里云语音评测；词级评分高亮
- **P5d 打磨**：VAD 自动断句、口语错题本 × 复习队列联动深化、Dataview 趋势模板

## 9. 成功指标

| 指标 | 目标 | 数据来源 |
|---|---|---|
| DV/CL/LK 码两周环比 | 持续下降 | error log 统计 |
| 同一考点重复求助次数 | 建议采纳后下降（弱点真被解决的证据） | 提问记录 |
| 建议卡片「不准确」反馈率 | 低于 20%（分析质量） | 建议卡片交互 |
| 复查队列按期处理率 | ≥ 80% | 复查记录 |
| 同一「考点+代码」复发 ≥3 次的条目数 | 趋零 | error log |
| 术语「已稳定」占比 | 每月上升 | 术语清单 |
| 雅思写作分项 | LR/GRA 先到 7.0，总分 7.5 | 作文档案 |
| 雅思口语模考分 | FC/LR/GRA/P 趋势向 7.5 靠近；P 无评测时不造假 | 练习报告 frontmatter |
| 口语练习发起方式 | 100% 主动发起（不打卡的自检项） | 练习记录 |
| 使用摩擦 | 结题到入库 ≤ 2 次点击；单次求助附加操作接近零 | 产品自查 |

注意：**不把「使用时长/频次」当成功指标**——辅助工具的理想状态是求助越来越少、每次越来越准。

## 10. 风险与开放问题

| 风险/问题 | 说明 | 对策 |
|---|---|---|
| AI 输出格式漂移导致解析失败 | log 行/术语行/会话标签格式不稳定 | prompt 中固定输出格式 + 解析失败降级手动粘贴；提问记录解析失败静默丢弃（行为日志丢一条不影响使用） |
| 提问样本太少，弱点分析不可靠 | 辅助工具使用频率低，前期数据稀疏 | 样本不足时不出建议卡片（阈值内置，如单弱点信号 ≥3 条），宁可不说不可乱说 |
| 提醒变成骚扰 | 督促过度引起反感，违背辅助定位 | 默认温和且只提醒插件内的事；长期堆积转建议卡片而非升级骚扰 |
| 档案「待确认事项」未定 | Further Maths 起始年、方向选择等影响配置 | 做成档案待办，插件不阻塞，确认后自动调整 prompt 参数 |
| prompt 与插件版本脱节 | 用户改了 prompts/ 文件 | 插件只注入不校验内容，保留 6000 字符提示 |
| 多设备同步冲突 | git / iCloud 并发编辑同一记录文件 | 追加为主的文件设计 + 按次分文件 + 冲突标记检测（见 §5） |
| 随手记归类错误 | AI 把进展误判为失分点等 | 所有提取必经确认；低置信度默认落学习日志，宁可不归类不可错归类 |
| iPad MediaRecorder 输出 mp4/AAC | 与桌面 webm 不一致 | 统一 decodeAudioData 解码 + 重采样成 16k WAV（纯 Web API，全链路通用格式） |
| 讯飞 WS 签名需要 crypto | 不能用 Node crypto（iPad） | Web Crypto API（crypto.subtle）全平台可用 |
| ISE 对开放式回答评分偏差 | 无固定 refText | 用 ASR 结果作 refText 评发音清晰度，报告中明确告知侧重 |
| 语音链路延迟 >3s 冷场 | 体验差 | 流式 LLM + 按句 TTS 流水线 + 考官过渡语先播 |
| Obsidian 移动端后台中断录音 | 系统限制 | 不做后台录音，UI 提示保持前台 |
| 语音 API Key 存储 | 同 LLM Key 一样只存本机 data.json | 设置页提示；建议为插件申请低额度 Key |

**已解决**（历史版本的开放问题）：独立新插件 + fork 复用；数据全部 vault 内 Markdown，不用二进制数据源；定位为辅助工具，周计划/每日待办从核心功能降级为可选附件。
