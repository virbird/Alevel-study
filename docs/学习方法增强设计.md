# 学习方法增强设计（借鉴 DeepTutor 学习方法层，v0.1.6+ 分阶段实施）

> 状态：Q1–Q4 全部落地并随 0.1.6 一并发布（原计划分 0.1.6/0.1.7 两批，用户确认合并发布）。
> 源起：二次分析 HKUDS/DeepTutor（v1.5.x）后确定的学习方法借鉴——检索练习优先、
> 元认知校准、注意力聚焦、交错编排。核心原则不变：本地优先、不代写、零新增 LLM 调用、
> vault 数据可审计、不加设置项（决策规则固定）。
> 实施偏差记录：Q2 分析旗标除画像/周快照外无独立 UI（与设计一致）；周快照旧 5 列表
> 在 0.1.7 升级表头并补 '-'（宽容迁移）。

## 总体思路：四个增强都围绕「已有数据的教学法再利用」

```
Q1 盲重做（检索练习：先盲做 → 再亮旧错 → 后对标准）      0.1.6
Q2 自评校准（元认知：埋点先行 → 数据够了再出旗标）        0.1.6 埋点 / 0.1.7 分析
Q3 本周三件事（注意力聚焦：首页一行摘要，非新面块）        0.1.6
Q4 交错编排（desirable difficulty：复习单科目轮转）       0.1.7
```

不新建台账、不新增文件（Q2 复用提问记录加列）；全部零 LLM、纯本地。

## 通用约束（沿用证据闭环设计，全阶段遵守）

1. **i18n**：所有新 UI 文案进 `src/i18n.ts` en/zh 双字典。
2. **零 LLM 依赖**：Q1–Q4 全部本地拼装/统计，不新增模型调用。
3. **测试**：每阶段追加 UT+FVT 并全量跑通（当前基线 484 项）。
4. **兼容**：台账加列采用「读时宽容（旧行缺列取空）、写时全列」策略，不迁移旧数据。
5. **不加设置项**：交错阈值、旗标判据等全部固定规则，写死并注释理由。

## Q1 附件式盲重做（0.1.6，约 1 小时）

**目标**：错题重做从「预填一句话」升级为符合检索练习原则的三步流：
先盲做 → 再对照当时的错误 → 后对标准做法。教学顺序是本设计的核心，不可颠倒。

### 方案（不解析会话、不加存储）
- 改造 `MainView.startWrongRedo(w)`（现于 MainView 约 L2085）：
  - 现状：切科目 → startSession → 预填 `wrong.prefill` 文本。
  - 新增：当 `w.session` 非空且 `会话/<session>.md` 存在时，把该存档
    **push 进 `this.attachments`**（复用现有 `{path, name}` 附件机制，与「引用」按钮同路径），
    随后预填新文案 `wrong.redo.blind`。
  - 会话文件不存在（未存档/被删）→ 降级为现行 `wrong.prefill` 行为，不报错。
- 预填文案（指令式，顺序控制交给 AI）：
  - en: `Redo wrong answer "{topic}". Step 1: give me the original problem (from the attached
    session) and let me attempt it blind — do NOT reveal my past mistake yet. Step 2: after I
    answer, contrast my new attempt with my original error in the attachment. Step 3: only then
    walk me to the standard approach.`
  - zh: `重做错题「{topic}」。第一步：根据附件会话给出原题让我盲做，先不要提示我当时的错误；
    第二步：我作答后，把新答案与附件里我当时的错误对比；第三步：再引导到标准做法。`
- 复习页签④与记录中心④的「去练」按钮均走此流程（同一方法，无分叉）。

### 为什么不本地解析会话抽「学生首条作答」
学生作答多为图片，存档中学生消息可能仅有占位文本；解析长多轮会话误抽风险高。
附件让 AI 全文可见（含它当时对错误的文字描述），准确性优于任何本地抽取。

### token 边界
会话存档偶有超长。附件注入沿用现有 attachment 读取路径，不做特殊截断
（现有机制已承担「引用文档」同量级内容；上下文用量条可见，超限可手动压缩）。

### i18n keys
`wrong.redo.blind`（en/zh）。现有 `wrong.prefill` 保留作降级文案。

### 测试
- UT：session 存在 → attachments 含该路径且预填为 blind 文案；session 空/文件缺失 → 降级 prefill。
- FVT：订正闭环入库（带 session）后触发重做，验证附件挂载 + 三步文案。

### 指标
错题「未订正→已订正」转化率（周快照已有未订正数列，环比可见）。

## Q2 自评校准（0.1.6 埋点 / 0.1.7 分析，各约半天）

**目标**：把结题六件套里已存在的「自评 1–5」落库，积累 3–4 周后输出
「过度自信失分码」旗标——自评高但随后复发的码，是元认知盲区，优先复习。

### 0.1.6 埋点（数据先行，本版只采不析）
- `SessionTag` 接口（types/index.ts L95）加可选字段 `selfRating?: string`（'1'–'5'，缺省 ''）。
- 打标指令（i18n `prompt.tagInstruction` en/zh 规则 1 的 JSON 模板）在 sessionTag 里
  增加字段：`"selfRating": "学生结题自评 1-5，未自评则省略"`。10 份科目模板不改
  （打标指令由代码统一注入，单点变更）。
- `QuestionLogService.appendTag`：行渲染从 5 列扩为 6 列
  `[date, subject, topic, confusion, depth, selfRating]`；提问记录台账表头加「自评」列。
  读取侧（InsightEngine.loadQuestionTags）宽容：旧 5 列行 selfRating=''。
- 记录中心⑤提问记录表格加「自评」列（i18n `records.cols.questions` 追加）。

### 0.1.7 分析（数据够了才上）
- `InsightEngine` 新增本地统计 `calibrationFlags(tags, entries)`：
  - 按**失分码聚合**（单学生考点级样本过稀，码级才有统计意义）；
  - 判据（固定）：某码关联的会话自评均值 ≥4 且该码 30 天内复发次数 ≥2 → 旗标
    「过度自信码」；反向（自评 ≤2 但从未复发）→「低估码」（仅展示，不催练）。
  - 样本门槛：该码带自评的会话 ≥3 条才参与计算，不足不出旗标（避免噪音）。
- 输出挂两处：弱点画像（ProfileL2Service 科目节尾加一行「校准：过度自信 E（自评均 4.3，
  复发 2 次）」带证据日期）+ 周快照追加「过度自信码数」一列。
- 不做独立 UI；画像与周报是既定出口。

### i18n keys
`records.cols.questions` 追加；`profile.calibration.over` / `profile.calibration.under`（若画像行文案走 i18n；
画像正文按数据文件约定保持中文，仅 UI 层翻译——与现行 weakness-profile 一致）。

### 测试
- UT（0.1.6）：appendTag 6 列往返；旧 5 列行解析 selfRating=''；sessionTag JSON 含 selfRating 时正确落列。
- UT（0.1.7）：calibrationFlags 判据边界（均值 3.9 不触发/复发 1 次不触发/样本 2 条不触发）；
  画像含校准行与证据。
- FVT：结题 → 提问记录含自评 → 画像重生成出现校准行（用构造数据满足门槛）。

### 指标
旗标码的后续复发衰减（周快照环比，人工观察即可，不自动断言）。

## Q3 首页「本周三件事」（0.1.6，约 2 小时）

**目标**：注意力聚焦。不建新面块、不做 Mastery Path——首页顶部一张卡，
列当周最该处理的 3 条，各带一句「为什么」和直达按钮。

### 数据与排序（全部复用现有队列，固定规则）
- 候选池：error-log 到期项（`dueEntries()` 已按 复发×逾期 排序）取前 2 +
  错题未订正（`wrongAnswers.open()`）按登记日最旧取 1；不足 3 条时按池内顺序补齐；
  全空则整卡不渲染。
- 不引入「考试临近度」（需新增设置项，违背固定规则原则；现有 复发×逾期 已足够）。
- 每条格式：`{科目} · {考点}（{一句理由}）` + 「去练」按钮：
  - error-log 条 → 复用现有 `startVariantDrill(e)`；
  - 错题条 → 复用 Q1 的 `startWrongRedo(w)`。
- 理由拼现有字段（i18n 模板）：
  - error-log：`复发 {n} 次、逾期 {d} 天`；
  - 错题：`登记 {d} 天仍未订正`。

### 渲染位置
`renderDashboard()`（MainView L242 起）中，插在「批改任务卡片」之后、
「待处理建议卡片」之前——它是行动清单，优先级高于建议流。

### i18n keys
`home.top3.title`（'This week, clear these 3 first' / '本周先清这 3 条'）、
`home.top3.reason.log` / `home.top3.reason.wrong` / `home.top3.go`。

### 测试
- UT：排序规则（2+1 组成、不足补齐、全空不渲染）——抽成纯函数 `pickTop3(due, openWrongs)` 供测。
- FVT：构造 3+ 到期项，验证卡片条目与按钮 mode 跳转。

### 指标
无新增（三件事清除即体现在既有周快照四列中）。

## Q4 复习单交错编排（0.1.7，约 2 小时）

**目标**：desirable difficulty——到期项够多时，复习单②「错题重做」小节内
按科目轮转穿插排列，替代当前的入队顺序，提升迁移。

### 规则（固定，不加开关）
- 触发条件：②节条目（points+wrongs 合并后）**≥6 条且跨 ≥2 个科目**才交错；
  否则维持现状顺序（小样本交错=噪音，注释写明理由）。
- 算法：**科目轮转（round-robin）**——按科目分桶（桶内保持原有优先级顺序），
  轮流从各桶取 1 条直至取尽。确定性、可解释；不用随机洗牌（复习单可再生，
  随机导致每次重生成顺序跳变）。
- 指纹不受影响（fingerprint 基于 ID 集合串，与顺序无关——现实现为 join，需在实现时
  改为**排序后 join**以确保顺序无关性，此为顺带修正）。
- ①术语闪卡、③表达造句节不交错（单一维度，无穿插意义）。

### 服务层
- `ReviewSheetService` 内加纯函数 `interleave<T extends {subject: string}>(items: T[]): T[]`
  （导出供测试）；`generate()` 内②节入列前套用。
- fingerprint 计算处 ID 串先 sort 再 join（同数据不同入参顺序 → 同指纹）。

### i18n keys
无新 UI 文案（复习单正文中文为数据文件约定；②节标题尾部加「（交错编排）」仅在触发时，
中文写死于正文，与现行小节标题一致）。

### 测试
- UT：≥6 且跨 2 科 → 轮转序正确（构造 3 科不均衡桶验证取尽逻辑）；5 条或单科 → 原序；
  指纹顺序无关（同集合乱序入参同指纹）。
- FVT：生成复习单验证②节排列与触发条件。
